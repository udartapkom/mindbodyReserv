# Фаза 5 — После MVP (бэклог оплат)

Это не блокер запуска оплат. Цель — довести продукт до нормальной подписки и операционки.

Рекомендуемый порядок: `tariffExpiresAt` + `priceAmount` → Telegram → сверка → возвраты → рекуррент (если нужен).

Каждый пункт — отдельная итерация с продуктовыми решениями.

---

## 1. Срок тарифа (`tariffExpiresAt`) и напоминания

**Сделано:**

- `users.tariff_expires_at`;
- `tariffs.duration_days` (trial=7, popular/vip=30);
- при webhook `CONFIRMED` выставляется/продлевается дата (тот же тариф с будущей датой — от `expiresAt`, иначе от `now`);
- cron ежедневно 03:00 UTC: истёк → `tariff = free`, `tariff_expires_at = null`;
- в кабинете (UserBar) и админке Users — «действует до …»;
- **напоминания (retention):**
  - UserBar: полоска при ≤3 днях / в день истечения / после истечения + CTA «Продлить» → `/price`;
  - Web Push за 3, 1 и 0 календарных дней (UTC) до `tariffExpiresAt` (cron 07:00 UTC);
  - преф `notifyTariffExpiry` (default `true`), тогл в профиле / PWA push card;
  - дедуп в `tariff_expiry_reminders` (миграция `015_notify_tariff_expiry.sql`).

Email-напоминания — не в этой итерации.

## 2. Рекуррентные СБП-подписки Platega

**Когда:** только если разовых оплат недостаточно.

**Сделать:**

- интеграция с recurring API Platega (привязка, списание, отмена);
- обработка failed charge;
- UI «Отменить подписку»;
- статусы подписки в БД;
- оферта / FAQ под автопродление.

Отдельный продуктовый кусок, не смешивать с разовой оплатой MVP.

---

## 3. Возвраты через Platega API

**Сделано:**

- админка «Вернуть» на оплаченных платежах → `cancel-supported` + `cancel` в Platega;
- статус → `chargeback`;
- если у пользователя тариф совпадает с платежом — сразу `free` + очистка `tariffExpiresAt`;
- webhook `CHARGEBACKED` после `paid` тоже обрабатывается (раньше игнорировался);
- VK-алерт о возврате.

**Политика:** при возврате/chargeback тариф снимаем сразу (если он ещё от этого платежа). Если пользователь успел купить другой тариф — не трогаем.

---

## 4. Выгрузка транзакций / сверка в «Бухгалтерии»

**Сделано:**

- фильтры по датам создания и статусам;
- суммы по статусам за выбранный период;
- экспорт CSV (UTF-8 BOM) по текущему фильтру;
- подсказка по сверке с ЛК Platega; точечная сверка pending/failed через «Сверить».

**Не делали:** автоматический bulk-reconcile со всеми транзакциями Platega за месяц.

---

## 5. Уведомление админу в VK

**Сделано в API:** `VkNotifyService` (`VK_BOT_TOKEN` + `VK_ADMIN_ID` из `bots/.env`).

События:

- оплата `CONFIRMED` → сообщение в ЛС админу;
- `CHARGEBACKED` → алерт (тариф не снимается автоматически);
- новый тикет поддержки → алерт со ссылкой на `/tickets`.

Если ключи не заданы — silently skip (только debug-лог).

Опционально: `ADMIN_PANEL_URL` (по умолчанию `https://admin.mindbodyhub.pro`).

Telegram (`TG_BOT_TOKEN`) пока не подключён — исключено из текущей итерации.

---

## 6. Нормализация `tariffs.price` → `priceAmount`

**Сделано:**

- числовое поле `priceAmount` в каталоге тарифов;
- `POST /payments/create` берёт `priceAmount`, иначе fallback на парсинг строки `price`;
- админка тарифов редактирует «Цена для оплаты (₽)» и «Срок доступа (дней)»; строка `price`/`period` — для отображения.
